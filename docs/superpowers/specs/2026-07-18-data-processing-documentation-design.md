# 数据处理流程文档整理设计

## 背景

仓库已有 `docs/current_pipeline.md` 和 `docs/runbook.md`，但内容与当前流水线不完全一致：流程顺序仍包含旧的 `fuse -> split_cycle` 描述，部分命令还在使用 `drivefusion` 环境。为了方便后续查询，需要将两份文档更新为中文，并以当前的 SAM3D-Body 双视角流水线为准。

## 目标

- 用中文清楚记录当前数据处理顺序及各阶段的职责。
- 同时提供流程概览和可直接执行的操作手册。
- 统一使用仓库规定的 `gymnastic` Conda 环境。
- 明确每一步的输入、输出、入口、验证方法和常见故障。
- 让后续使用者能够从 README 快速找到权威文档。

## 非目标

- 不修改数据处理代码、配置或实验参数。
- 不实际重跑 SAM3D-Body、周期切分、三角化、融合或训练任务。
- 不重新设计旧的 `legacy/prepare_dataset` 流程。
- 不复制第三方模块的安装文档或模型下载说明。

## 文档组织

采用两份文档分工的方式：

1. `docs/current_pipeline.md`
   - 作为当前流水线的概念说明和权威流程入口。
   - 记录前置条件、端到端顺序、数据流、关键目录、模块职责和当前推荐方法。
   - 链接到 `docs/runbook.md`，供需要执行命令时继续阅读。
2. `docs/runbook.md`
   - 作为可执行操作手册。
   - 分别记录单个人和全数据集的运行步骤、命令、预期输出、结果检查及故障排查。
   - 链接回 `docs/current_pipeline.md`，避免重复解释设计背景。
3. `README.md`
   - 更新文档入口和简短流程描述。
   - 不在 README 中复制完整操作手册。

## 权威流程

文档统一采用以下顺序：

```text
同一人的 face/side 原始视频
  -> SAM3D-Body 逐帧关键点提取
  -> face/side 时间对齐与动作周期切分
  -> 使用 2D 关键点三角化生成 3D 伪真值
  -> face/side 3D 关键点融合
  -> 与三角化伪真值比较和分析
  -> 可选的分类模型训练与评估
```

完整流水线需要同一人的 `face + side` 两个视角。只有一个视频时，只能执行单视角 SAM3D-Body 推理，不能完成双视角对齐、三角化和融合。

## 必须记录的技术事实

- 原始视频默认位于 `/home/data/xchen/gymnastics/raw/person`。
- SAM3D-Body 结果默认位于 `/home/data/xchen/gymnastics/sam3d_body_results/person`。
- `split_cycle` 负责 face/side 时间对齐和周期切分。
- 对齐记录位于 `logs/split_cycle/person_<id>/alignment_record_<id>.json`。
- 三角化读取周期帧记录及 SAM3D 2D 关键点，结果位于 `/home/data/xchen/gymnastics/sam3d_triangulated/person`。
- `fuse` 必须使用切分阶段记录的 `offset_side_to_face`，不回退到重新估计的关键点 DTW 偏移。
- 当前推荐融合方法是 `sim3_face_stable_smooth_kpt`：以 face 为参考，使用稳定关节估计 Sim3，将 side 对齐到 face，平均两个视角，再进行时间平滑。
- 融合结果与三角化 3D 伪真值比较，主要报告 MPJPE 等指标。
- 分类训练属于可选下游阶段，使用已准备的动作数据和人员级折叠映射。
- 所有项目命令默认通过 `conda run -n gymnastic ...` 执行。
- 旧的 DPT、RAFT、YOLO 和 Detectron2 路径只作为 `legacy/prepare_dataset` 参考流程记录。

## 操作手册结构

单人处理部分使用通用占位符 `<person_id>`，并补充一个具体示例，避免使用者误把示例编号当成固定参数。步骤包括：

1. 检查 face/side 原始视频。
2. 运行该人的 SAM3D-Body 推理。
3. 检查两个视角的逐帧 `.npz` 输出和日志。
4. 运行时间对齐与周期切分。
5. 检查对齐记录及周期视频。
6. 运行三角化，可先进行小规模冒烟检查。
7. 检查三角化序列、摘要、可视化及重投影误差。
8. 运行融合实验。
9. 检查融合序列和按人统计指标。
10. 按需生成分析报告或执行分类训练。

全数据集部分提供同样顺序的入口命令，但不重复单人部分的详细解释。长时间或 GPU 密集步骤需要明确标注，避免被误认为快速检查命令。

## 验证方式

文档更新后进行以下静态验证：

- 检查所有入口文件、配置文件和文档链接真实存在。
- 对照当前代码的命令行参数，确认单人及冒烟测试命令有效。
- 搜索并移除活动流程中的 `drivefusion` 环境命令。
- 搜索旧的 `fuse -> split_cycle` 顺序，确保不再被描述为当前流程。
- 检查文档中没有未完成标记或未解释的占位符。
- 检查 README、流程概览和操作手册之间没有矛盾。

由于本任务只修改文档，不执行耗时的数据处理与训练任务。

## 完成标准

- 三个目标文件对当前流水线的描述一致。
- 新用户能从 README 找到中文流程概览和操作手册。
- 用户能按操作手册处理一个人的 face/side 视频，并知道每一步应检查什么。
- 文档明确区分必需的数据准备步骤、融合评估和可选分类训练。
- 文档不会把历史流程或旧 Conda 环境误写成当前推荐做法。
